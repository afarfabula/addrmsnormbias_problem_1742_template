# AddRmsNormBias 提交/测试结果记录

> 目的：把每一次 `git commit` 对应的精度与性能测试结果固定下来，方便回溯与对比。
>
> 约定：
> - 本地核时（`dev_avg_us`）：`cd build && ASCEND_VISIBLE_DEVICES=3 ARNBS_NOSYNC=1 ARNBS_TIMES=300 ./add_rms_norm_bias_custom`
>   或 `python3 /tmp|../scripts/runone` 生成指定 shape。300 次热迭代均值；注明 `reps` 若不同。
> - 精度回归：`cd build && ASCEND_VISIBLE_DEVICES=3 python3 ../scripts/run_accuracy.py`（16 case，
>   vs torch-native 与 vs numpy-golden，误差元素占比 <=1e-3 判 PASS）。
> - 重负荷回归：`cd build && ASCEND_VISIBLE_DEVICES=3 python3 ../scripts/run_heavy_accuracy.py`。
> - 榜单（官方评测系统）15 点成绩由用户回贴记录，未回贴的 commit 阶段标 `-`。

## v4 — 放宽分组路径：对齐行 D≤2048 全量走 tile/WholeReduceSum
- 内容：`AddRmsNormBiasGroup` 门槛从 `D%64==0 && D<=512` 放宽到「fp32: D%8==0；
  fp16/bf16: D%16==0（行首在 fp32 工作区 32B 对齐）且 64<=D<=2048」；γ/β 参数缓冲改
  为按 D 动态分配；行内平方和折叠支持非 64 整数倍的尾部窗口（D=96/1152/1536 等），
  再交给硬件 WholeReduceSum。覆盖官方“真实模型”常见维度 96/192/256/384/512/576/
  768/1024/1152/1536/2048（含非 2 幂、非 64 倍）。D=100 类行首非对齐、D>2048 的
  大宽行仍走 `AddRmsNormBiasKernel` 保底路径。
- 精度：`run_accuracy.py` 16/16 ALL PASSED；新增 7 个大 shape 抽样（D=96/1152/1536/
  576，fp16+fp32，rows 4K~32K）vs numpy fp32 golden 全部 0 错误元素。
- 本地热迭代对比（同口径 dev_avg_us，μs；改造前→改造后）：
  | shape | dtype | 改造前(legacy) | 改造后(group) | 提升 |
  |--|--|--|--|--|
  | `[2048,576]` | fp16 | 54.6 | 22.2 | 2.5x |
  | `[1024,576]` | fp16 | 30.6 | 14.4 | 2.1x |
  | `[4096,96]` | fp16 | 91.0 | ~24 | ~3.8x |
  | `[2048,1152]` | fp16 | 60.8 | 35.8 | 1.7x |
  | `[8192,576]` | fp16 | ~198 | ~72 | ~2.8x |
  | `[32768,576]` | fp16 | ~770 | ~255 | ~3.0x |
  | `[8192,2048]` | fp16 | ~254 | ~204 | ~1.25x |
  | `[8192,576]` | fp32 | 175.5 | 74.6 | 2.4x |
  | `[1024,2304]` | fp32 | 69.0 | 57.7* | D>2048 未吃到 |
  | `[8192,100]` | fp16 | 229.7 | 229.7* | 行首非对齐未吃到 |
- 结论：本地 probe 与官方点“错位”的主因基本确认——官方“真实模型”D（576/1152/96 等）
  大多不在旧 gate 内，导致优化吃不到；本轮把这些形状全部并入高速路径。
